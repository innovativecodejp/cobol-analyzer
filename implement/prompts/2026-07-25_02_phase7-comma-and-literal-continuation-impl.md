## 実装タスク

### タスク 1：共有リテラル追跡スキャナ（§3.5「リテラル追跡の共有」）

1 つの状態機械で、行テキストを走査して以下を判定するスキャナを実装する。§3.1 の継続と §3.5 の両方がこれを使う（**片方だけの実装にしない**）。

- 非数字リテラル（`'…'` / `"…"`）の内部か。二重引用符エスケープ（`''` / `""`）を正しく扱う。
- 擬似テキスト（`== … ==`）の内部か。
- 行内注記（リテラル外の `*>` 以降）は行末まで注記扱い。
- 走査開始状態（継続用に「直前行末が開いたリテラルか・引用符種別」）を受け取り、走査後の終端状態を返せること。
- 各文字位置が「保護対象（リテラル/擬似テキスト/注記の内部）」かのマスクを返せること（§3.5 のカンマ判定に使う）。

### タスク 2：§3.1 リテラル行継続の是正（CBSTM03A 型）

col7 `-` 継続で、直前の論理行が**開いたリテラルの途中**で終わっている場合、継続行 Area B の**先頭引用符（再開クォート）を除去**してから連結する（COBOL のリテラル継続規則）。リテラル外の継続は従来どおり直接連結（最小対応）。判定はタスク1のスキャナ終端状態で行う。

### タスク 3：§3.5 区切りカンマ正規化（§3.4 の後段）

パイプライン順（§3.6）：§3.1 → §3.2 → §3.3 → §3.4 → **§3.5**。EXEC/SQL 縮約後に実行することで SQL の `SELECT A, B` 等に触れない。

規則：**「カンマ + 直後空白（または採用後の行末終端）」のカンマ 1 文字**を、**空白 1 文字へ同一長置換**（桁位置保存）。ただし保護対象（タスク1のマスク：リテラル/擬似テキスト/注記の内部）は対象外。
- PIC 句（`PIC ZZ,ZZ9`）・`DECIMAL-POINT IS COMMA`（`1,5`）は「直後が空白でない」ため規則上自動的に非対象。**PIC/文脈追跡は実装しない**。
- 空白を伴わない添字カンマ（`TBL(I,J)`）は非対象（§9）。

### タスク 4：テスト（§7-5・§8）

`tests/CobolAnalyzer.Parser.Tests/` に実ファイルフィクスチャで追加：
- §3.5 単体：`USING A, B`（正規化）、`PIC ZZ,ZZ9`（不変）、`DECIMAL-POINT IS COMMA` の `1,5`（不変）、リテラル内 `'a, b'` / `'Segoe UI,sans-serif'`（不変）、擬似テキスト `== A, B ==`（不変）、EXEC 縮約後にカンマ非残存、行末終端カンマ（`STRING A,` 改行 `B`）、**同一長・桁位置保存**。
- **§7-5 golden 非破壊性**：`'… Segoe UI,sans-serif …'` を含むリテラル行を固定し、§3.5 前後でリテラルが不変であることをアサート（成功率だけでは検出できない静かな破壊を防ぐ）。
- リテラル追跡が col7 `-` 行継続を跨ぐケース（CBSTM03A 型）。

### タスク 5：CardDemo 再スパイク（§7-3）

`tools/CardDemoSpike` で再測定し、以下を確認・記録（`implement/log/working/`）：
- Batch **CB* ≥ 11/12**、うち **CBACT01C–04C / CBTRN01C–03C を必須 pass**。
- CICS **CO* ≥ 17/18**。
- §3.5 導入でリテラル破壊が無い（golden test green）。
