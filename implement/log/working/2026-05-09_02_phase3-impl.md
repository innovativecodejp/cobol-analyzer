**Editor.ts**: Monaco Editor ラッパー。`language: 'plaintext'`、`automaticLayout: true`。  
Monaco Worker は `main.ts` 内で `window.MonacoEnvironment` を設定（`editor.worker?worker` の Vite `?worker` 構文）。

**AstTree.ts**: `d3.tree()` 水平レイアウト（`nodeSize([28, 160])`）。ノード色は NodeCategory 別（Structure: `#1a4fa8` / Unit: `#2e86c1` / Element: `#808080`）。クリックで `collapsed` トグル後に再描画。`d3.zoom()` でパン・ズーム。

**CfgGraph.ts**: `d3.forceSimulation`（linkDistance 80 / charge -200 / center）。角丸矩形ノード（120×40px）。エントリ: 緑 / エグジット: オレンジ / 通常: 水色。エッジは 8 種類を色・線種（実線/破線/点線）で区別。最大 200 ブロック制限あり（超過時は警告テキストを SVG 上に表示）。`d3.drag()` でノード手動配置。`d3.zoom()` でパン・ズーム。

**DfgGraph.ts**: CfgGraph と同設定の forceSimulation。ノードは円形（isGroup: r=14 / 通常: r=8）、`hasRedefines=true` で赤枠。Define/Use エッジに SVG arrowhead marker（色別: 赤・青）、Redefines はオレンジ破線、GroupOf はグレー実線（矢印なし）。

**MdiPanel.ts**: MDI スコア（2rem 太字）・リスクバッジ（リスク別背景色）・指標別バーチャート（CC/GD/AD/ND/RD/CS の加重寄与値を縦棒で表示）をインライン DOM 生成。

## 仕様差分・技術上の判断

### 1. tsconfig に `skipLibCheck: true` を追加

`tsc` が `node_modules/vite/dist/node/index.d.ts` および `node_modules/monaco-editor/esm/vs/editor/editor.api.d.ts` の型競合を検出してビルドエラーとなった。  
- `vite/node` の型は `@types/node` を要求するが、フロントエンドプロジェクトに node 型は不要
- Monaco が宣言する `Window.MonacoEnvironment` の型と独自宣言が競合

**対処**: `skipLibCheck: true` を追加（node_modules 内 .d.ts の型チェックをスキップ）。フロントエンド Vite プロジェクトでの標準的な対応。

### 2. `Window.MonacoEnvironment` の独自宣言を削除

`vite-env.d.ts` に独自の `interface Window { MonacoEnvironment? }` を定義したところ、Monaco 側の同名宣言（`Monaco.Environment` 型）と競合してエラーとなった。  
**対処**: 独自宣言を削除し、Monaco の global 型拡張をそのまま利用。`main.ts` では型エラーなく `window.MonacoEnvironment` を設定できる。

### 3. AstTree の `d3.linkHorizontal` 型エラー

`hierarchy.links()` の戻り値型が `HierarchyLink<T>` のままで、`HierarchyPointLink<T>` が要求する `.x` / `.y` プロパティ（`number` 確定）と互換しなかった。  
**対処**: `treeLayout(node)` の戻り値 `HierarchyPointNode<T>` を使用し、`.links()` / `.descendants()` を `pointRoot` から取得することで型を確定させた。

### 4. `analyzeBtn` の型

`document.getElementById()` は `HTMLElement | null` を返し、`disabled` プロパティは `HTMLButtonElement` に存在するため型エラー。  
**対処**: `as HTMLButtonElement` キャストに変更。

### 5. MdiPanel バッジ色テストの jsdom 正規化

jsdom では `element.style.backgroundColor = '#27ae60'` と設定した後に読み出すと `rgb(39, 174, 96)` に正規化される。  
**対処**: テスト内でアサートする値を `rgb(39, 174, 96)` / `rgb(231, 76, 60)` に合わせた。

### 6. Monaco の `?worker` インポートタイミング

ES モジュールの静的 import は評価順が制御困難なため、Monaco Worker 設定（`window.MonacoEnvironment`）は `main.ts` のモジュール本体（import 宣言より後のスクリプト部）で行い、`monaco.editor.create()` はボタンクリック時にのみ呼ぶ構造にした。これにより Worker 設定が `create()` より確実に先行する。
