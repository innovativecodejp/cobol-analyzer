# Phase 7（前処理）仕様：実コード対応の前処理層

- 起票日: 2026-07-25
- 前提スパイク: `../log/working/2026-07-24_01_carddemo-parse-spike.md`

## §1 目的・背景

実用規模の実 COBOL（AWS CardDemo, Apache-2.0）を解析対象にできるようにする。スパイクの結論：現行パーサが実コードで全滅する原因は**コア文法の限界ではなく、固定形式などの前処理が入力パイプラインに無いこと**。詰まりは有界であり、前処理層を入れれば解消できる。

本仕様は、そのための**前処理層**を定義する。これは Phase 7（実コードデモ）の共通土台であり、デモ（ギャラリー / 静的インタラクティブ）に先立つ enabler。

## §2 スコープ / 非スコープ

**スコープ（本仕様）**
- 固定形式の正規化（連番欄・指標欄・コメント・継続・73–80 無視）
- 旧式 IDENTIFICATION 段落の除去（AUTHOR. 等）
- COPY のテキスト展開（単純メンバコピー）
- EXEC CICS / EXEC SQL ブロックの構文通過対応（意味論は最小）
- 上記を経て CardDemo のバッチ系（CB*）がパース成功すること

**非スコープ（将来フェーズ）**
- COPY ... REPLACING（CardDemo で1本のみ。既知の制約として扱う）
- EXEC CICS の完全な意味論解析（本フェーズはブロックを不可視化して周辺ロジックを解析可能にするに留める）
- コピーブック内の入れ子 COPY の完全再帰展開（一段は必須、多段は best-effort）

## §3 前処理の要件

前処理は「生ソース → 正規化済みソース文字列」を生成し、それを既存の `Cobol85Lexer`/`Cobol85Parser` に渡す。前処理は**文字列変換**として実装し、行番号の対応（原本行 → 正規化後行）を可能な範囲で保持する（エラー位置報告のため）。

### §3.1 固定形式の正規化
- **連番欄（col 1–6）**: 無視（コード領域から除外）。数字連番の有無どちらも許容。
- **指標欄（col 7）**:
  - `*` / `/` → コメント行。除去する。
  - `-` → 継続行。直前行の続きとして連結する（最小対応。文字列リテラル継続の厳密対応は best-effort）。
  - 空白 → 通常行。
- **コード領域（col 8–72）**: 採用。
- **識別領域（col 73–80）**: 無視。
- 行長が 7 以下の行、空行を安全に扱う。

### §3.2 旧式 IDENTIFICATION 段落の除去
以下の段落行を除去（または無害化）する。CardDemo では AUTHOR. が 24/44、DATE-WRITTEN. が 5/44：
- `AUTHOR.` / `INSTALLATION.` / `DATE-WRITTEN.` / `DATE-COMPILED.` / `SECURITY.`
- 段落見出し行と、それに続く自由記述行（次の段落/DIVISION/SECTION まで）を除去する。

### §3.3 COPY のテキスト展開
- 形式 `COPY member-name.`（大小文字非依存）を、コピーブックの内容で置換する。
- メンバ解決：**設定可能なコピーブック検索パス**（複数可）から `member-name` に一致するファイル（`.cpy` / `.CPY` 等、拡張子候補は設定）を探す。
- 置換内容自体も §3.1 の正規化を適用する（コピーブックも固定形式）。
- 一段展開は必須。展開後に現れる COPY（入れ子）は best-effort（深さ上限を設け、循環は検出して停止）。
- 解決できないメンバは、**エラーにせず**「未解決 COPY」として警告に記録し、当該行を無害化（プレースホルダ）する。
- `COPY ... REPLACING ...` は本フェーズ非対応。検出したら警告に記録し、単純展開 or 無害化（挙動を実装プロンプトで確定）。

### §3.4 EXEC CICS / EXEC SQL ブロック
- `EXEC CICS ... END-EXEC` / `EXEC SQL ... END-EXEC`（行跨り可、`.` 有無両対応）を検出し、**構文を通すための最小縮約**を行う。
  - 既定方針：ブロックを不可視のプレースホルダ文へ縮約（例：`CONTINUE` 相当の no-op 文）に置換し、周辺の PROCEDURE ロジックを解析可能にする。
  - 縮約したブロックは「exec ブロックが存在した」旨を警告 or メタ情報として残す（将来の意味論解析のフック）。
- 本フェーズでは CICS 意味論（送受信・制御遷移）の解析は行わない。

### §3.5 区切りカンマの正規化 ― **採用（2026-07-25 決定, 旧 §9.1）**

COBOL の任意区切り文字であるカンマを現行文法（生成済み `Cobol85Parser`）が `CALL … USING A, B` / `STRING A, B` 等で受け付けないため、前処理で空白へ正規化する。CardDemo では **CBACT04C.cbl / CSUTLDTC.cbl** の詰まりがこれのみで、対応により Batch 11/12（うち §8 代表バッチ CBACT04C が pass）。

**判定規則（「カンマ + 直後空白」の 1 文字先読み）**：以下をすべて満たすカンマ **1 文字** を、**空白 1 文字**へ**同一長置換**する（行・桁位置を保存 = `ParseWarning.Line` の整合性のため）。
- **直後の文字が空白**、または符号化領域の**行末終端**（col 72 まで採用後の行末）である。
- 英数字／各国語**リテラルの内部でない**。
- **擬似テキスト**（`== … ==`）の内部でない。
- **EXEC … END-EXEC ブロックの内部でない**（§3.4 の縮約適用**後**に本処理を行うことで、SQL の `SELECT A, B` 等に COBOL 区切り規則を誤適用しない。処理順は §3.6 で規定）。
- 注記でない（col 7 の `*` `/`、および `*>` 以降）。

**PIC 句の除外は不要**：区切りカンマの定義が「カンマ + 直後空白」であるため、PIC 挿入文字（`PIC ZZ,ZZ9` はカンマ直後が `Z`）と `DECIMAL-POINT IS COMMA` の小数点（`1,5` はカンマ直後が数字）は規則上自動的に非対象になる。よって PIC 文脈・環境部（`DECIMAL-POINT`）の先読み追跡は行わない（コピーブック単独解析時の設定不明問題も回避）。

**非対象（§9 に残す）**：空白を伴わないカンマ（`TBL(I,J)` のような添字カンマ）は本規則では処理しない。対応するには PIC/文脈追跡が必要で利点が消えるため、CardDemo で実害が無い間は着手しない。

**リテラル追跡の共有**：リテラル内判定は行継続（col 7 `-`）をまたぐ必要があり、これは §9 の CBSTM03A（HTML リテラルの行継続）と**同一のリテラル追跡状態機械**である。両者は 1 つのリテラル追跡スキャナで実装し、片方だけの実装にしない。

**実装位置**：既定は本前処理層でのテキスト正規化（案 2）。字句規則に隠しチャネル送り（`COMMASEPARATOR : ',' ' ' -> channel(HIDDEN);` を `COMMACHAR` より前に配置, 案 1）で実装してもよい（リテラル除外を lexer が自動処理）。ただし文法にオプショナル `COMMACHAR` を足す案（案 3）は**採らない**（区切り空白が書ける場所すべてに波及し規則が無限に広がるため）。

### §3.6 前処理パイプラインの処理順（確定）

前段の出力を次段が受ける。区切りカンマは EXEC 縮約の後に置く。
§3.1 固定形式正規化 → §3.2 旧式 ID 段落除去 → §3.3 COPY 展開（展開テキストにも §3.1 適用）→ §3.4 EXEC CICS/SQL 縮約 → **§3.5 区切りカンマ正規化**。

## §4 配線点

- 前処理は `CobolAnalyzer.Parser` 内の新クラス（例：`CobolPreprocessor`）に実装する。
- `CobolParserFacade.Parse(string source)` の**先頭で前処理を適用**し、正規化済みソースを lexer へ渡す。これにより `CobolSourceParser`（API `/api/parse`）およびプロジェクト解析（`IProjectSourceParser` 経由）**すべての呼び出しに一括で反映**される。
- 前処理は既定で ON。ただし**テスト互換のため**、前処理を経ても現行の自由形式テストデータ（`hello.cbl` 等、col 8 始まり・連番なし）が引き続き成功すること（§7）。

## §5 設定

- コピーブック検索パス・拡張子候補を、Facade もしくは前処理器に**注入可能**にする（デモ時は CardDemo の `app/cpy` を指す）。
- 単一ファイル解析（コピーブック未指定）でも動作すること（未解決 COPY は §3.3 の警告扱い）。

## §6 データモデル・挙動

- `ParseResult` の形は不変（`Ast` / `Errors` / `IsSuccess`）。
- 前処理由来の非致命的事象（未解決 COPY、REPLACING、深さ超過、循環、EXEC 縮約）は `Errors` とは別の**警告**として表現する。**確定（2026-07-25 実装）**：`ParseResult` に `Warnings`（`List<ParseWarning(int Line, string Kind, string Message)>`、`Kind` は `ParseWarningKind`）を追加。`IsSuccess` は従来どおり `Errors.Count == 0` で不変。既存 API 契約は非破壊。
- 例外を投げない（既存方針を踏襲）。

## §7 受け入れ基準

1. `dotnet build` / 既存 `dotnet test` がグリーン（前処理導入で既存パーサ/AST テストを壊さない）。
2. 既存の自由形式テストデータ（`hello.cbl` / `data-sample.cbl` / `goto-sample.cbl`）が前処理経由でも `IsSuccess = true`。
3. **CardDemo 再スパイク**：`app/cbl` を対象に測定し、**バッチ系（CB*）の大半がパース成功**すること。本数・閾値は実コーパスに合わせる（下記注記）。CICS 系（CO*）は §3.4 適用後の改善を測定・記録（構造解析可能な水準を目標）。

   > **本数の確定（2026-07-25 再スパイク実測）**：取得した CardDemo（`aws-samples/aws-mainframe-modernization-carddemo`, shallow clone）の `app/cbl` は **CB* が 12本 / CO* が 18本 / CS* が 1本**（当初仕様の「CB* 14本」は誤り）。前処理配線時点の実測は **合計 27/31**（Batch **10/12**・CICS **17/18**・Other 0/1）。
   > - **目標は絶対数でなく「比率＋名指しファイル」で規定する**（上流のファイル増減で破綻しないため）。バッチ目標：**CB* ≥ 11/12**、うち **CBACT01C–04C / CBTRN01C–03C を必須 pass**。§3.5（区切りカンマ）採用で CBACT04C が pass し 11/12 を満たす見込み。
   > - CICS 目標：§3.4 適用後に **CO* ≥ 17/18** 相当の構造解析可能水準。
   > - 本数は submodule 化（コミットハッシュ固定, タスク2）で確定させる。以後の閾値は固定した版を基準にする。「CB* 14本」の出所（別リビジョン or `app/cbl` 以外を含めた可能性）は submodule 固定時に一度確認し、同種のズレの再発を防ぐ。
4. 測定は**再現可能なテスト or スクリプト**として残し、pass/fail 一覧とエラーバケットを出力する（スパイクのハーネスに相当するものを `implement/` 内に正式化してよい）。
5. **正規化の非破壊性（§3.5 導入に伴う必須）**：`'… Segoe UI,sans-serif …'` のように「カンマ + 空白」を含み得るリテラル行を golden test に固定し、**§3.5 正規化の前後でリテラルトークンが不変**であることをアサートする。無条件置換によるリテラル破壊はパース成功のまま静かに通るため、成功率（27/31 等）だけでは検出できない。

## §8 テスト

- 前処理器の単体テスト：固定形式正規化（連番あり/なし、コメント col7、継続、73–80）、旧式 ID 段落除去、COPY 展開（解決/未解決/一段/入れ子上限）、EXEC 縮約。
- **§3.5 区切りカンマの単体テスト**：`USING A, B`（正規化する）、`PIC ZZ,ZZ9`（触らない）、`DECIMAL-POINT IS COMMA` の `1,5`（触らない）、リテラル内 `'a, b'` / `'Segoe UI,sans-serif'`（触らない）、擬似テキスト `== A, B ==`（触らない）、EXEC 縮約後にカンマが残らないこと、行末終端カンマ（`STRING A,` 改行 `B`）、同一長・桁位置保存。リテラル追跡は行継続（col7 `-`）を跨ぐケースを含める（CBSTM03A 型）。
- 統合：CardDemo の代表バッチ（例 `CBACT04C`（§3.5 で pass）/ `CBTRN02C`）＋対応コピーブックで、`IsSuccess = true` と AST の主要ノード生成を確認。
- テストデータは実ファイル読み込み（ハードコード禁止、既存方針踏襲）。CardDemo 由来ファイルを test fixture に取り込む場合は Apache-2.0 ヘッダ/帰属を保持。

## §9 既知の制約（明記する）

- COPY REPLACING 非対応（CardDemo で **COACTUPC.cbl** の1本のみ影響。§3.3 で警告＋無害化するが、当該ファイルは高複雑度 CICS ロジックと相まって pass せず）。
- EXEC CICS の意味論解析は未対応（構文通過のみ）。
- 継続行・特殊桁の厳密対応は best-effort。ただし §3.5 のリテラル追跡スキャナを共有して実装するため、CardDemo の **CBSTM03A.CBL**（HTML を含む `VALUE` リテラルの col7 `-` 行継続）は §3.5 と同時対応する（従来の「据え置き best-effort」から格上げ）。
- **空白を伴わない添字カンマ**（`TBL(I,J)` 等）は §3.5 の対象外。PIC/文脈追跡が必要で、CardDemo に実害が無いため非対応（将来フェーズ）。

> **区切りカンマ（旧 §9.1）は §3.5 で採用に確定**（2026-07-25, Opus 5 レビューを受けて）。当初案の「リテラル外・PIC 句外」のうち **PIC 句外条件は不要**と判明（「カンマ + 直後空白」規則で PIC・`DECIMAL-POINT IS COMMA` は自動的に非対象）。詳細は §3.5。
